# معايير القبول الاحترافية لـ Backend

## الهدف

لا تُعتبر أي وحدة مكتملة لمجرد أن البناء ينجح أو أن المسار يعيد استجابة صحيحة في حالة واحدة. يُعتمد الإنجاز فقط عندما يحقق منطق الأعمال، وعزل الشركات، والصلاحيات، والذرية، والتدقيق، والاختبارات، والأداء، والتشغيل متطلبات الإنتاج معاً.

## بوابات القبول الإلزامية

| البوابة | معيار القبول |
|---|---|
| صحة البيانات | كل عملية تجارية تُنفذ داخل معاملة ذرية، وتتحقق من جميع العلاقات التابعة لنفس الشركة قبل الكتابة. |
| عزل الشركات | لا يمكن للمستخدم أو الجهاز أو العملية أو الاستعلام قراءة أو تعديل سجل يخص شركة أخرى، حتى مع تغيير المعرفات في الطلب. |
| الصلاحيات | كل مسار إنتاجي محمي بـ JWT وصلاحية مستقلة مناسبة، مع فصل صلاحيات القراءة والإنشاء والتعديل والحذف عند الحاجة. |
| المزامنة | Push لا يسجل العملية فقط؛ بل يتحقق منها وينفذ منطقها التجاري، ويكون قابلاً لإعادة الإرسال دون تكرار أو فساد بيانات. |
| المحاسبة | كل بيع وشراء ودفع ومرتجع ومصروف ينتج الأثر المحاسبي والمخزني الصحيح، ويمكن تتبعه وإلغاؤه أو عكسه وفق قواعد واضحة. |
| المرتجعات | المرتجع مرتبط بالمعاملة الأصلية، ويمنع تجاوز الكمية أو التكرار، ويحدث المخزون والأرصدة والقيود في معاملة واحدة. |
| التدقيق | كل تغيير حساس يسجل المستخدم والجهاز والشركة والكيان والقيم السابقة واللاحقة والوقت. |
| الاختبارات | اختبارات وحدات، وتكامل، وE2E، وعزل شركات، وصلاحيات، وتعارض مزامنة، وفشل جزئي، واستعادة بعد انقطاع الاتصال. |
| الإنتاج | migrations قابلة للتكرار، نسخ احتياطي واستعادة مختبران، health checks، logging، rate limiting، إدارة أسرار، ومراقبة أخطاء. |

## نتائج التدقيق الأولي

أظهر الجرد الحالي أن وحدات المحاسبة والمخزون والمنتجات والمشتريات والمبيعات والتقارير محمية بدرجات متفاوتة، بينما توجد Controllers إنتاجية تحتاج إلى تدقيق وحماية صريحة، وهي: `users`, `companies`, `settings`, `audit`, `printing`, و`whatsapp`. كما أن `sync` يستخدم JWT ويتحقق من هوية الجهاز، لكنه لا يفرض صلاحية مخصصة ولا يطبق العملية التجارية؛ فهو يسجل `SyncOperation` بحالة `SYNCED` مباشرة.

اختبارات E2E موجودة لعدة وحدات، لكنها لا تعتبر ناجحة حتى تعمل ضد PostgreSQL مخصص للاختبار. آخر تشغيل فعلي فشل بسبب غياب `DATABASE_URL` في البيئة، ولذلك لا يجوز إعلان اجتياز الاختبارات.

## ترتيب التنفيذ الاحترافي

1. إغلاق فجوات الحماية في جميع Controllers، بما في ذلك المسارات التي لا تحتوي حالياً على `JwtAuthGuard` أو `PermissionsGuard`.
2. تثبيت عقد مزامنة versioned مع حالات `PENDING`, `PROCESSING`, `SYNCED`, `FAILED`, و`CONFLICT`، وربطها بمنطق الأعمال الحقيقي.
3. إعادة بناء المرتجعات والمحاسبة حول معاملات ذرية وسجلات أصلية قابلة للتتبع.
4. إضافة اختبارات العزل والتلاعب وإعادة الإرسال والفشل الجزئي والتعارضات.
5. إعداد PostgreSQL للاختبار، migrations، مراقبة الأداء، النسخ الاحتياطي، والاستعادة.
6. اعتماد كل وحدة فقط بعد تحقيق جميع بوابات القبول أعلاه.
